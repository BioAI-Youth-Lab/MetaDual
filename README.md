# MetaDual

**Learning disease-relevant relationships among individuals enables multi-disease prediction from the gut microbial abundance profiles**

Tingzhi Deng†, Wenwen Yu†, Yuanyuan Yu, Fan Yang, Jinting Guan, and Ying Wang*

Xiamen University, Fujian, China

† Equal contribution. * Corresponding author.

This repository accompanies the supplied MetaDual manuscript. MetaDual integrates species abundance profiles and LLM-derived functional profiles through cohort-level attention, fixed profile-similarity graphs, and adaptively learned disease-relevant relationships among individuals. The task is multiclass classification of disease groups and healthy controls in a **transductive** setting.

## Manuscript results

| Cohort | Individuals | Groups, including healthy controls | Fixed test set | Macro-AUC | Macro-F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Primary | 4,012 | 7 | 799 | 0.9812 | 0.8546 |
| Independent | 6,025 | 8 | 1,202 | 0.9244 | 0.6996 |

These are manuscript-reported means across five repeated runs. The archived source CSVs agree with these values after rounding; they were not generated by a new full training run during repository preparation. See [results](results/README.md) and the [consolidated metrics](results/summary.csv). The independent cohort is trained and evaluated within that cohort, rather than tested using a model trained only on the primary cohort.

## Installation

The Conda environment is named `MetaDual`, with Python 3.10.16, PyTorch 2.7.0 / CUDA 12.6, NumPy 1.26.4, pandas 2.2.3, SciPy 1.15.3, scikit-learn 1.6.1 and Transformers 4.51.3. From the repository root:

```bash
conda env create -f environment.yml
conda activate MetaDual
```

If this environment already exists, activate it directly. Alternatively install `requirements.txt`, or `requirements-notebook.txt` for notebook support. Exact observed versions are in [environment_snapshot.json](docs/environment_snapshot.json). GPU/driver compatibility depends on the PyTorch build. Full-cohort attention is memory intensive; CPU execution is intended for small checks.

For notebooks, register the kernel after activating the environment:

```bash
python -m ipykernel install --user --name MetaDual --display-name "Python (MetaDual)"
```

## Train MetaDual

```bash
# Primary cohort: 4,012 individuals, seven groups
python -m model.train --cohort primary --variant full --device cuda

# Independent cohort: 6,025 individuals, eight groups
python -m model.train --cohort independent --variant full --device cuda
```

Both processed feature datasets are included. The independent NPZ uses lossless compression, with every original array and dtype preserved. Dataset schemas, class mappings and counts are in [DATA.md](docs/DATA.md).

Profiles are specified in [configs/primary.json](configs/primary.json) and [configs/independent.json](configs/independent.json). They use Bray–Curtis fixed graphs, hidden size 768, `K=3`, learning rate 0.02, weight decay 0.0005, epsilon 0.9, `r=3`, up to 3,000 epochs and patience 300. The exported primary source defaults use dropout 0.5; the independent source defaults use 0.55. The full historical launch commands are not recoverable from the metric CSVs, so these portable profiles must not be interpreted as a guarantee of identical manuscript numbers.

Explicit arguments override a cohort profile:

```bash
python -m model.train --cohort primary --data /path/to/features.npz \
  --dropout 0.55 --epochs 3000 --output-dir outputs/model
python -m model.train --help
```

The test set is fixed by stratified sampling with seed 42. Each of five runs re-partitions the remaining individuals into training/validation using seeds 0–4 and a 75% training fraction, giving approximately 60/20/20 after rounding. All individual profiles are available during graph construction and attention; only training labels optimize parameters, and validation labels select checkpoints. These are **repeated runs over a fixed test set**, not five-fold cross-validation.

Each invocation creates `outputs/model/<cohort>/<variant>/<timestamp>/`. Per-run outputs include the best checkpoint, split indices, training history, predictions, probabilities, sample IDs and metrics. Aggregate files include per-run and per-class metrics, confusion matrices, and mean/std summaries. CSV standard deviations use `ddof=1`; the population accuracy standard deviation is also recorded in `summary.json`.

## Model architecture and ablations

For each view, MetaDual projects the input, applies a shared four-head cohort attention block, and concatenates contextualized and projected features. Fixed-graph propagation retains powers 2 and 3 when `K=3`. A second branch sums four learned cosine-affinity heads, retains positive threshold/top-r connections, symmetrizes them, adds self-connections, and propagates projected original inputs. Both views are concatenated, scaled feature-wise, and mapped to group scores with an output attention block. Training minimizes negative log-likelihood.

| `--variant` | Experiment |
| --- | --- |
| `full` | MetaDual with abundance and functional profiles |
| `abundance_only` | Removes the functional view; corresponds to the manuscript's missing-functional-profile ablation |
| `function_only` | Removes the abundance view; corresponds to the manuscript's missing-abundance-profile ablation |
| `no_structure` | Removes the adaptive-affinity branches, retaining fixed graphs and contextual attention |
| `no_modifiedt_1` | Additional component ablation removing feature-level context attention |
| `no_modifiedt_2` | Additional component ablation removing feature-level and output context attention |

```bash
bash model/run_all.sh --cohort primary --device cuda
```

Historical class names remain compatible with the source checkpoints; `MetaDual` is the paper-facing alias. See [METHODS.md](docs/METHODS.md) for the equation-to-code correspondence.

## Functional profiles and data preparation

A functional profile concatenates the first two 768-dimensional BiomedBERT CLS vectors. Each vector encodes five ordered FCG Function statements, truncated to 512 tokens. Text embeddings remain fixed during MetaDual training. The abundance and functional features contain no demographic covariates in the model input.

The primary dataset can be rebuilt from the bundled abundance CSV and archived FCGs without new API requests:

```bash
python -m data_processing.pipeline prepare
python -m data_processing.pipeline embed --embed-model /path/to/BiomedBERT --device cpu
python -m data_processing.pipeline merge
```

Outputs go to `outputs/data/` and existing outputs are not overwritten. BiomedBERT weights are not bundled; use a local model directory or a model identifier. The independent processed NPZ is supplied directly; its upstream abundance preprocessing and original FCG responses are not bundled in this repository.

To explicitly generate new manuscript-style descriptions using the selected prompt and Top 50 species:

```bash
export DEEPSEEK_API_KEY='YOUR_KEY'
python -m data_processing.pipeline generate --preset manuscript
```

The method specification follows the manuscript: Top 50 nonzero species are supplied to DeepSeek-V3.2. The packaged precomputed datasets are retained unchanged and do not require new API requests. `DEEPSEEK_MODEL` configures the provider model identifier; source-script settings and API-alias provenance are recorded in [CODE_PROVENANCE.md](docs/CODE_PROVENANCE.md).

## Diversity-aware prompt development

Read the archived **30 → 15 → 8** rankings offline:

```bash
python -m prompt_search.search history
```

The selected historical prompt is [best_prompt.txt](prompt_search/prompts/best_prompt.txt), hash `168f2812`. It asks for at least ten FCGs of two to five species, explaining cross-feeding, co-metabolism, syntrophy and other complementary functions. Historical candidate scores are prompt-selection observations, not the manuscript's final cohort performance.

The cleaned [notebook](prompt_search/prompt_search_agg_no.ipynb) opens offline. To start a new online search matching the manuscript's Top 50 input and validation-based selection:

```bash
export DEEPSEEK_API_KEY='YOUR_KEY'
python -m prompt_search.search run --preset manuscript \
  --pair-refinement --embed-model /path/to/BiomedBERT --device cuda
```

Candidate combinations are ranked by summed pairwise BiomedBERT cosine distances. Four-parent and three-parent stages target 15 and 8 improved prompts after 30 initial generation attempts. The optional two-parent refinement implements the additional stage described in Methods 4.3. No target is filled by duplicating prompts; partial counts are reported. The archived two-parent attempt log contains zero accepted candidates and a stale baseline; it is preserved separately rather than presented as a newly successful stage.

The default preset scores validation predictions, following Methods 4.3. The historical ranking JSONs and selected prompt are retained unchanged. See [PROMPTS.md](docs/PROMPTS.md) for search settings and [MANUSCRIPT_ALIGNMENT.md](docs/MANUSCRIPT_ALIGNMENT.md) for the manuscript-to-repository mapping. Online commands call a paid API and train multiple GCNs; neither is needed to use the bundled datasets or inspect results.

## Repository layout and reproducibility coverage

```text
configs/             Portable training profiles for the two manuscript cohorts
model/               MetaDual, component ablations and shared training engine
data_processing/     Feature preparation and the two processed datasets
prompt_search/       Search/scoring code, clean notebook, prompts and history
results/             Archived metrics for MetaDual and six baseline methods
docs/                Data, methods, provenance and manuscript-alignment notes
tools/               Offline verification
verification/        Small verification reports
```

The archived baseline results cover random forest, MLP, Meta-Spec, GCN, GAT and MixHop with abundance, functional and combined inputs. Their original training implementations and the manuscript's full UMAP, theme-analysis and biomarker figure-generation pipelines are not bundled; see the explicit coverage table in [MANUSCRIPT_ALIGNMENT.md](docs/MANUSCRIPT_ALIGNMENT.md). This repository provides the main MetaDual training, selected ablations, functional-profile pipeline, prompt development and verifiable historical metric records.

```bash
python tools/verify_export.py
python tools/verify_manuscript.py
```

The checks make no API calls and perform only short synthetic training. Preparation-time reports are in `verification/`. See [VERIFICATION.md](docs/VERIFICATION.md) for numerical comparisons, source-integrity checks and their limits. Raw source datasets and original experiments were not edited, and no manuscript text was used to overwrite historical numerical results.
